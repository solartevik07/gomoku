# Gomoku (5 в ряд) 

## Правила

- Чорні (гравець) ходять першими.
- Виграє той, хто першим виставить 5 своїх каменів підряд —
  по горизонталі, вертикалі або діагоналі.
- Клік по перетину ліній ставить камінь.

## Структура проєкту

```
gomoku/
├── main.py      — точка входу, запускає вікно гри
├── gui.py       — інтерфейс на tkinter, обробка кліків, потік для ШІ
├── board.py     — стан дошки: ходи, скасування ходів, перевірка виграшу
├── ai.py        — увесь алгоритмічний "мозок" ШІ
└── README.md
```

## Які алгоритми застосовані (в `ai.py`)

### 1. Minimax
Базовий алгоритм пошуку по дереву гри. ШІ (гравець, що максимізує
оцінку) і людина (яку ШІ моделює як гравця, що мінімізує оцінку)
почергово роблять ходи в уявній грі на кілька півходів вперед; ШІ
обирає хід, який веде до найкращого результату за умови, що
супротивник теж грає якнайкраще.

### 2. Альфа-бета відсікання
Оптимізація minimax: якщо під час перебору стає зрозуміло, що
супротивник ніколи не дозволить дійти до якоїсь гілки (вона вже гірша
за раніше знайдений варіант), ця гілка відкидається без повного
перебору. Не змінює результат пошуку, лише прискорює його — часто
на порядки.

### 3. Ітеративне поглиблення
ШІ шукає спочатку на глибину 1 хід, потім 2, 3 і так далі, поки не
вичерпається ліміт часу на хід (задається складністю). Це дає
компроміс: чим складніший суперник, тим глибше він встигає порахувати,
і завжди повертається найкращий хід, знайдений на останній
завершеній глибині.

### 4. Обмеження кандидатів на хід
Дошка 13×13 має 169 клітин — перебирати всі на кожному рівні дерева
нереально. Тому розглядаються лише порожні клітини в радіусі 2 від
уже зайнятих.

### 5. Впорядкування ходів
Перед повним пошуком кандидати сортуються за
оцінкою того, наскільки хід підсилює власні лінії. Це дозволяє альфа-бета відсікати гілки
значно ефективніше, бо найкращі ходи перевіряються першими.

### 6. Евристична оцінка позиції
Коли пошук доходить до максимальної глибини, потрібно оцінити
наскільки хороша позиція. Дошка сканується вікнами по 5 клітин уздовж
усіх ліній (горизонталі, вертикалі, обидві діагоналі). Якщо у вікні
немає каменів супротивника, воно додає очки власнику за кожен камінь
у ньому (за таблицею `WINDOW_SCORE`, де більше каменів підряд коштує
експоненційно більше). Підсумкова оцінка позиції — це різниця
"власних" і "чужих" очок.

Для швидкодії оцінка рахується не по всій дошці, а лише в bounding box навколо вже зроблених ходів,
розширеній на 4 клітини в кожен бік.

### 7. Миттєва перевірка виграшу/блокування
Перед повним пошуком окремо перевіряється чи є хід, що виграє одразу,
і чи є хід супротивника, що виграє одразу (і його треба заблокувати).
Це гарантує коректну гру навіть на малій глибині пошуку.
